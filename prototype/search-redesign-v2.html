② 方案 A（推荐）· 全高双栏 · 左「键+搜」右「热+看」

推荐

思路很简单：让每一栏里都加一段「可长可短」的区块，去认领剩余高度。 键盘把键帽撑高到电视友好的尺寸（约 300px），左栏下方补最近搜索； 右栏下方补继续观看海报墙（这一段用 flex:1 吸收全部余量，行数随窗口自动增减）。 四块内容都是已有真实数据，不需要新接口。

为什么不用「把键盘拉到满高」这一招：
中间行 604px 全靠键盘吸收的话，字母区每行要变成 (604−16)÷3 ≈ 196px 高 —— 键帽比海报还高，看着像坏掉了。所以键盘封顶在 300px（字母行 ~93px、数字行 ~68px， 已是电视遥控器舒适尺寸的上限），余量交给内容区去填。
数据来源（都是现成的，无新接口）：
· 热门搜索 → DoubanHotService.GetHotWordsAsync()（TVBox 同源，实测可用）
· 最近搜索 → 本地 Preferences 历史词（已有 GetHistory()）
· 继续观看 → play_history 表，带封面（PlayHistoryEntry.Cover）
· 片名联想 → search_index 表 + 历史 + 收藏 + 热词，按片名聚合
空数据时对应区块整段隐藏，布局自动上移，不留在那里占位。

✅
建议走 方案 A：它用「键盘封顶 300px + 内容区吸收余量」这一条规则， 就把空白问题从根上解掉，而且窗口怎么拉都不空 —— 继续观看是 flex:1， 海报行数随高度自动增减。
另外方案 A 的结构天然容纳后续状态：输入态右栏换成联想列表、 结果态键盘整栏收起，三种状态共用同一套栅格，不需要分别调布局。
三端一致：以上是横屏单套布局 —— 手机 / 平板 / 电视 / Windows 共用（本项目既定约定）。 在手机上「继续观看」会自动变成 3 列（窄屏），规则同样是 flex:1 + 自适应列数，不写死。

注意：焦点默认落点由「热门搜索」改为可用时，底部提示条必须跟着改 （现在写死的是 移动 / 输入或激活 / 退格或返回，且右侧焦点指示只有「热门搜索 1/10」一种）。 新布局有 4 个可聚焦区，提示条右侧应显示当前区名 + 区内序号，否则用户不知道自己站在哪。
