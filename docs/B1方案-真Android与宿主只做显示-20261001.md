# B1 方案：把 guest 变成"真 Android 设备"，宿主只做显示

> 目标（用户诉求）：像真正的安卓设备一样运行，Windows 宿主只做显示（+ 输入转发 + 原生播放）。
> 本文记录 2026-10-01 的侦察结论、选型、体积账、启动契约差异与分阶段计划。

---

## 一、结论先行

- **可行**：108 上已用真 Android（Waydroid + 我们自己的 ndk_translation + 手机同款 APK/数据）跑通全套，
  证明"真 Android + 我们的壳"这条路成立。
- **但 B1（在我们自己的 QEMU guest 里起完整 Android）是数天级系统工程**：
  拦路虎不是"缺文件"，而是 Android `init` 的**启动契约**与我们的 initramfs 环境不匹配（见 §三）。
- **体积可以很小**：若沿用 Waydroid 血统 + guest 内 Wayland 合成器，预计 **285MB → 约 305MB**（+20MB），
  无需任何外部大下载。

---

## 二、可用资产清单（都在 108 上，已实测分类）

| 镜像 | 大小 | 类型 | 含什么 |
|---|---|---|---|
| `/var/lib/waydroid/images/system.img` | 1726MB | ext4 | **我们 guest 的母本**；`bin/adbd`(1.68MB)、`system/bin/surfaceflinger`、`apex/com.android.adbd/bin/adbd`、`lib64/libadbd_{auth,fs}.so` |
| `/var/lib/waydroid/images/vendor.img`（=`vendor-ex/vendor.img`） | 535MB | ext4 | `hwcomposer.waydroid.so`(508KB)、`gralloc.gbm.so`(41KB)、`gralloc.minigbm_gbm_mesa.so`、`libEGL_mesa.so`/`libGLESv2_mesa.so`、`libgallium_dri.so`(**41MB**)、`libgbm_mesa.so`、`libdrm.so`、20 个 rc |
| `/root/x86guest/SuperOut/{system,product,system_ext,vendor}.img` | 868+1812+168+96MB | ext4 | 官方 Android 13 x86_64（ChromeOS sdk_gphone，ndk_translation 同源）：`bin/adbd`、`libndk_translation.so`、`hwcomposer.ranchu.so`(599KB)、`libEGL_emulation/angle`、39 个 rc |
| `/root/x86guest/sysimg-ex/x86_64/{kernel-ranchu,ramdisk.img,build.prop}` | — | — | 官方模拟器内核/ramdisk；`build.prop` 证实 **sdk=33 / x86_64 / native.bridge=libndk_translation.so** |
| `/root/x86guest/sysimg-ex/x86_64/system.img` | 4107MB | GPT，p2 无文件系统魔数 | **已损坏/半成品，不可用** |

**关键缺口**：三套镜像都**没有 `hwcomposer.drm.so`**（virtio-gpu 直连所需的合成器 HAL）。
- 官方/waydroid 的 HWC 分别依赖「模拟器宿主端渲染器」与「Wayland 合成器」。
- SourceForge 被 Cloudflare 挡（403 / `Just a moment...`），**无法**下载 Android-x86/Bliss ISO 去抠 `hwcomposer.drm`。
- ⇒ 选 **Wayland 路线**：复用已被验证的 `hwcomposer.waydroid` + weston（**从 108 的 Debian 直接拷最小集，无需下载**）。

## 三、启动契约差异（B1 真正的难点）

| Android `init` 期望 | 我们的现状 | 影响 |
|---|---|---|
| `/system`、`/vendor`、`/product` 由 first-stage 按 **fstab**（含 dm-verity）挂载 | 它们是 **initramfs 里的普通目录** | 挂载阶段失败/跳过 |
| **APEX** 由 `apexd` 用 loop+dm-verity 挂载 | 我们为 artlaunch **解包成目录** | apexd 起不来 ⇒ ART/zygote 缺运行时 |
| `property_service` + `ueventd` + SELinux 上下文库 | 我们绕过 init，用 `proppreload.so` 假装属性 | 真 init 起来后属性/上下文缺失 |
| 需要 composer HAL 才能起 SurfaceFlinger | 只有 waydroid/ranchu 版 | SF 起不来 ⇒ 无画面 |
| `/data` 需可写且带标签 | tmpfs 可写，标签无所谓（permissive） | 基本 OK |

**对策**（B1.1 要做的事）：
1. 内核 cmdline 补 `androidboot.hardware=ranchu androidboot.selinux=permissive androidboot.force_normal_boot=1`（走 permissive 绕开大半标签问题）。
2. 造最小 `fstab`：把已有目录声明为挂载点（或用 `ro.build.system_root_image=true` 让 init 视 `/` 为 system）。
3. APEX：优先验证"**flattened**"路径（`/system/apex/<pkg>` 已是目录时 apexd 可直接用），否则改为保留 `.apex` 文件并让 apexd 挂。
4. HAL：`hwcomposer.waydroid.so` + guest 内 weston（headless）→ 之后用 `screencap` 验画面。
5. 保留现有 artlaunch 线路不动，用 `FULLBOOT=1` 开关切换，随时可回退。

## 四、体积账（用户要求"尽可能小"）

| 方案 | 增量 | 风险 |
|---|---|---|
| **① 抠件补进现有小 guest（选定）** | **+约 20MB**（adbd 2MB + weston 及其库 10~20MB + rc 0.1MB） | 中（启动契约移植工作量） |
| ② 换 Android-x86/Bliss 基座 | +600MB~1.5GB | 低，但与"小体积"冲突；且 SF 被 Cloudflare 挡，拿不到 ISO |
| ③ 自搞 Wayland 合成器 | +10~20MB | 中高（同 ①，但显示链要自己写） |

GL **可以不要**：SurfaceFlinger 用 Skia CPU 合成即可（108 上已验证无 GL 也能渲染 UI）。

## 五、分阶段计划与验收

| 阶段 | 内容 | 验收标准 | 体积 |
|---|---|---|---|
| **B1.0** | 把 `adbd` 装进现有 guest：`bin/adbd` + `lib64/libadbd_{auth,fs}.so` + init 拉起 + 宿主 hostfwd `tcp:127.0.0.1:<port>-:5555` + 预置 adb key（或 `ro.adb.secure=0`） | `adb connect 127.0.0.1:<port>` 进得去 guest，能 `ls /data` | +2MB |
| **B1.1** | 造"完整 Android"启动线路（真 init + fstab/apex 适配 + waydroid HWC + guest 内 weston） | Android 起至能 `adb exec-out screencap -p` 出画面 | +12~20MB |
| **B1.2** | scrcpy 式投屏进 Windows 应用（SurfaceFlinger 虚拟显示 + MediaCodec H.264 + 宿主接收端解码上屏） | 在窗口里点按/滑动 Android 界面 | 小 |
| **B1.3** | 保留宿主原生播放（壳给地址 → 宿主播）；账号页/cookie 全部交给 Android | 播放画质/性能不回退 | 0 |

**先做 B1.0 的理由**：它小、可验证，且**立刻提升一切排障能力**（shell / 推拉文件 / logcat / screencap），
对 B1.1 的迭代和当前夸克那条线都有直接收益。

## 六、关键命令（B1.0 起步）

```bash
# 108：把被抠的件导出到本地（从 Waydroid 母本镜像）
M=/mnt/wd; mkdir -p $M; mount -o ro,loop /var/lib/waydroid/images/system.img $M
cp $M/bin/adbd                       /root/b1_blobs/adbd
cp $M/system/lib64/libadbd_auth.so   /root/b1_blobs/
cp $M/system/lib64/libadbd_fs.so     /root/b1_blobs/
umount $M
# 108：weston 及依赖（B1.1 用；挑最小集）
ldd /usr/bin/weston | awk '{print $3}' | grep '^/' | sort -u
```
