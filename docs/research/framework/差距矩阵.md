## 二、本次审计推翻或修正的既有结论

1. **"apex 挂载 ✗（我们没有 apex 内容）"** —— 错。6 个必需 APEX 已以**解包目录**形式在 `/apex`，
   运行时可见，`apex-info-list.xml` 全部 `isActive=true`；参照系在 `ro.apex.updatable` 未设时也只是 overlay。
   ⇒ apex 从"大工作量"降级为"让 apexd 认目录模式"。（`guest-apex.txt` / `108-reference.txt`）
2. **"`__system_property_area_init` = -1 疑因缺 SELinux 策略"（B1 文档第 16 条）** —— 至少**不是充分解释**：
   参照系 `getenforce=Disabled` 却完整跑着 framework，我们运行时也已 `Disabled`。
   而属性区那 268 项是**init 建的文件**（`properties_serial`/`property_info`/per-context），
   context 名来自 `plat_property_contexts`（我们镜像里已有 85 KiB）。
   ⇒ 结论改成"待实验 E1 定因"，不再当作"必须先补 SELinux"的依据。
3. **"我们没跑真 init ⇒ 需要移植 init"** —— 不需要移植：`/system/bin/init` 2,337,688 B 在镜像里，
   运行时也在位（`ls -l` 实测），69 个 rc 同样在。缺的只是**让它当 PID1**（现在是 `/bin/busybox sh /init`）。
4. **第一次运行时探针报"init/apexd 不在 /system/bin"** —— 是探针自己的输出被 `proppreload` 的每进程日志搅乱
   造成的假象；改成"每条问句单独一次 shell 调用 + 过滤该日志"后，7 个关键二进制全在。
   ⇒ 记进 `探针清单与判读.md` 的坑清单：**guest 里任何 adb shell 输出都要先滤掉 proppreload 行**。
5. **"`do=config` 是宿主自造的占位词"（扫码链路那轮的记录）** —— 现场探针 13 ms 就推翻：
   当前壳对 `do=config` 回 200 / 5,912B「输入配置」HTML 页，而 `do=input` 反而 400 `Unknown proxy action`。
   ⇒ 词表随壳版本变，静态结论要定期用 HTTP 探针复核。
