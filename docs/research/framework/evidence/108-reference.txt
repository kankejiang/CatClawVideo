      / `--skip-sepolicy`（init 支持吗要在第一步实验里验，别猜）。
    · 运行日志里 denial 计数见上：若为 0 且我们当前**根本没加载策略**，那「属性区失败因为缺 SELinux」这条就**只是巧合**，需要下面的实验来判。
    · 第一步可验证实验（只读、不改镜像；由 T1 注入或经 adb shell 手跑）：
        在 guest 里执行 `propinit`（blobs/propfix）并抓 bionic 的 libc 日志行 ——
        bionic 在 area_init 失败时会把**具体原因**写进 log（`failed to initialize system properties area` + errno/路径）。
        判读：出现 EPERM/`/sys/fs/selinux`/`u:object_r:` ⇒ SELinux 假设成立；
              出现 EEXIST/`already`/`/dev/__properties__` 路径类 ⇒ 是**目录或重复初始化**问题，与 SELinux 无关，路线 (B) 的属性服务成本骤降。
