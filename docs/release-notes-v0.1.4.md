猫爪影视 v0.1.4 —— 本次更新以 **「Guard 壳源播放链路修复」** 为主线：把困扰用户的「玩偶等 Guard 加固源点播放即弹『源不受支持』」从根上修掉。

> 自 v0.1.3（2026-09-23）以来累计的主线工作是 x86 mini guest 转译运行时联调（见 `docs/交接-x86迷你guest.md`），本次发布聚焦其中**已验收**的用户可见修复。

## 一、播放修复：Guard 源「源不受支持」（本次主线）

### 现象

玩偶（Guard 主源）加载、浏览、选集全部正常，**点播放即弹「播放失败：源不受支持（视频编码或容器格式不兼容）」**；日志见 `流透传失败: unexpected end of stream`。

### 根因

Guard 加固的多个源来自**同一个壳 jar**（玩偶 / seed / 荐片 / MDrive / 光影…），它们的壳内部**约定使用同一个本地流服务端口 6678**——**谁最近被装载，谁的服务就占住端口**。

而应用打开播放页时会自动做**跨源预取**（对其它站点搜索+解析选集，换源秒开用）——预取会顺带装载其它 Guard 族站点，**把当前源的流服务顶掉**：当前源 `playerContent` 仍返回写死 `127.0.0.1:6678` 的地址，请求打到「不认识这部片」的服务上 → 服务端 handler 抛空指针 → 连接秒断 → 播放器报「源不受支持」。

### 修复（四层）

- **播放前端口守卫**：播放 Guard 族源前，若期间有同族站点被装载过，自动**强制重装载本源**（3.5 秒，重建壳状态、重新占回端口）再解析播放地址；
- **跨源预取排除同 jar 站点**：预取候选不再包含与当前源同 jar 的兄弟站（同壳同质，预取收益低，从源头避免顶端口）；
- **桥侧 `load` 支持强制重载**（绕过「已装载」缓存，供守卫调用）；
- 桥调试直通工具（`CATCLAW_BRIDGE_DEBUG=1`）——面向排障的桥内取证通道。

### 验证

实验矩阵（scripts 沉淀于 `JavaBridge/qemu-src/tools/x86guest/`）：
仅装玩偶 → 探针 200 OK + 真实视频流；装入同族 seed → 立刻失效（0B）；
强制重装玩偶 → 3.5s 恢复 200 OK 且持续稳定。

## 二、x86 mini guest（实验性开发线，本次不随包）

「QEMU + WHPX 跑 x86_64 的 Android 13」转译运行时联调取得关键进展（详见 `docs/交接-x86迷你guest.md`）：

- Guard 壳解密→真实 dex→解析→**播放**全链路打通（三根因修复：注册时序 / namespace 判定 / 运行时回调表）；
- 补齐 ui_stub.dex 进 initrd（缺它 Guard 壳初始化即崩）；
- 108 联调环境补宿主 DNS 转发与完整工具链（探针/组装/替换脚本 20 余个）。

**本次发布不含 x86 组件**：该线路为实验性（`CATCLAW_X86_GUEST=1` 开关），播放链路尚有收尾项；验收完成后将作为独立特性发布（安装包届时 +约 280MB）。
