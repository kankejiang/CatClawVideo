猫爪影视 v0.1.4 —— 自 v0.1.3（2026-09-23）以来共 **106 个提交**，两条主线：

> **① 爬虫运行时大迁移**：Windows 端 jar 爬虫桥整体搬进 QEMU（真 Android ART 里就地执行），并**全量退役 Java 环境**（随包 JRE 与宿主回落桥一并撤除）；
> **② 一批播放稳定性与体验修复**（Guard 源「源不受支持」、磁力选集、搜索/首页提速、冷启动进度等）。

安装包：`catclaw.video-0.1.4-Setup.exe`（**314MB**，v0.1.3 为 238MB 基线 + ART guest 运行时，本期再瘦身 −80MB Java + −24MB 实验组件）。

---

## 一、爬虫运行时大迁移：QEMU ART guest 唯一化 + JRE 全退役

**「跑爬虫不再需要 Java」是本版最大的架构变化。**

- **jar 爬虫改跑 QEMU 里的真 ART**：TVBox/壳 jar（含 Guard 加固包）在 guest 里由真 Android 9 的 ART 直接吃 dex，ARM 原生码（解密 so）就地执行；**unidbg 离线解壳器退役**（它自建 Android 桩「看着对而语义不同」，还占 33MB）。
- **guest 能力补齐**：UI 事件通道（对话框/扫码/Toast 上行宿主渲染）、云盘播放链路（壳流中转地址经隧道透传，guest 里 6678 → 宿主可达）、guest 偏好持久化双向同步（**网盘 Cookie 重启不再丢**）。
- **迅雷引擎合并进 ART guest**：磁力下载与爬虫桥共用同一个 VM（外部 VM 模式），省 ~2.5GB 内存与一次内核冷启动；合并 initrd 两处致命 bug 同步修复，108 实机全链路验收通过。
- **冷启动 41s → 11.1s**：boot 镜像 + 预置 oat 进打包流水线（41s 基线实为测试 harness 干扰的污染样本）；专项运行时最终回退至验证可用的旧版（网盘源优先），提速成果保留。
- **initrd 重压缩**：zstd-19 把 585MB cpio 从 gzip 226MB 压到 **164MB**；纯桥版 initrd 退出安装包（合并版是它的超集）。
- **JRE 全退役（收官）**：随包精简 JRE（60.9MB）与宿主 JRE 回落桥（连同 dex2jar 转换管线 19.7MB）整条撤除——宿主不再有任何 Java 进程，`CATCLAW_NO_ART=1` 从「切回落」变为「整体禁用 jar 爬虫链路」；纯 .class jar 的 d8 预转换改用系统 Java（有就用，没有则该类源明确报错）。

## 二、播放与磁力修复

- **Guard 源「源不受支持」根治**（四层）：同 jar 家族多源共享壳内流服务端口 6678，跨源预取把当前源的服务顶掉 → 播放前强制重装载本源抢回端口（实测 3.4s、100% 恢复）+ 预取排除同族站点 + 桥侧 load 支持强制重载。
- **磁力合集选集不按文件拆分**：流式展开被 12 条上限误杀，放宽到 60；「退出播放页→重播同片必 9128」修复（EXIT 重启 harness）；流式选集接口从未生效的声明缺失补上 + 端口撞车自愈。
- **danmaku 钩子链、纯 .class jar 直通、op 挂死看门狗**；push 型聚合条目不再把内嵌 JSON 喂给播放器，给可读错误。
- **桥超时治理**：超时先探桥生死再重置（慢源不再连累整桥）；detailContent 会话缓存（聚合网盘源 71s 的 detail 不再重付）；并发起车互斥修「90s 超时」+ 桥预热；探针接管后误 Dispose 桥流致全站「Cannot access a disposed object」修复。
- 首页固定卡类目无限翻页修复（网盘「配置」8 张卡不再滚成 40 部）。

## 三、搜索与首页体验

- **搜索提速**：桥 per-site 并行 + 按历史速度调度（快源先出、慢源短超时）。
- **跨源并行预取**：当前线路慢（实测 71s）时其它源同时解析，换线路秒开。
- **冷启动遮罩**：41s 冷启动期间显示分阶段进度条 + 大号百分比数字（分段锚定：前段快推 / 80 后缓爬）；修「数字永远停在 80 多」（就绪先显示 100% 再淡出）；文案按平台区分（Android 显示「正在启动爬虫运行时」）。
- 首页首屏填充保底（第一页不满一屏自动续载）；切站后分类点击无反应修复。

## 四、订阅与站点管理

- **多订阅并存**：站点表按 Key 合并，不再首个成功独占。
- **单选启用开关**：启用谁就只显示谁的站点；开关双向化；停用后列表整块消失修复。
- 图片隐写订阅新形态兼容（盐前缀 + base64 配置）。

## 五、直播（TVBox 移植）

- 频道抽屉 / 换台 / EPG / 直播源配置页完整移植；订阅自带直播源**自动导入**（饭太硬实测）；Windows 下顶部 chips/设置面板避开系统标题栏按钮行。

## 六、网盘与网络媒体

- **Guard 系网盘源接入**：TVBox 云盘配置兼容层（对话框/扫码 UI 桥 + android 桩补全）、网盘入口走爬虫 action 链路、目录卡按 action/tag 分派（失败原因不再被吞）。
- **WebDAV 网络媒体**：连接管理 + 远程浏览 + 本地流代理；本地 tab 改名「视频库」并重排，直播入口挪到首页右侧。
- jarbridge 桩修复一批：**扫码登录「扫了码也没用」**（轮询节拍 20 倍 + 时钟同源）、prefs 落盘改读-改-写（多桥互相覆盖登录态）、Handler/View 延迟任务真实执行、SystemClock/Toast/DexNative 系列补齐。

## 七、JS Spider 引擎

- TVBox 社区 JS Spider 引擎落地：Jint 装配，`csp_` 源全链路真机打通。

## 八、工程与瘦身

- **依赖闭包法瘦身**（黑名单法 → 依赖闭包法，根治 libpdfium/libavif 误判事故）；initrd 大文件退出 git 历史（GitHub 100MB 限制）。
- **安装包瘦身批次 1**：剔 x86 实验引擎（24.3MB）——solid 压缩下与 aarch64 引擎高度重合，实测只省 1.2MB，教训已存档。
- **孤儿进程治理**：桥 JVM 与 QEMU VM 不再变孤儿（KillOnClose job + 代际号防旧 VM 复活，一次开发会话实测遗留 17 个 java.exe 的问题根治；多 qemu 并存事故修复）。
- **Android 端同步**：与 Windows 同源更新（端口守卫/预取过滤/编译修复）。
- vCPU 按虚拟化方式分配：WHPX（x86）给宿主逻辑核一半，TCG（aarch64）保持 4。

## 九、x86 mini guest（实验线，本版不随包）

「QEMU + WHPX 跑 x86_64 的 Android 13」联调持续推进（宿主开关默认关）：桥 9s 就绪里程碑、Guard 壳解密→播放全链路打通、合并 guest 实机验收通过。播放链路尚有收尾项，验收完成后将作为独立特性发布。
