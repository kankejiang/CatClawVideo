```
在 D:\Code\CatClawVideo 先读三个文件：
  docs/research/framework/路线对比与推荐.md（重点：E1/E2 实验、给 T1 的请求 R1/R3）
  docs/research/framework/差距矩阵.md（第 1/2/8 行：属性区 0 项、init.svc.* 0 条、PID1=busybox sh）
  docs/tasks/T1-显示栈收敛.md

背景（T4 审计结论，证据齐）：镜像文件层几乎全有——/system/bin/init 2,337,688B 在位、
69 个 rc（79 service/212 on/107 setprop）与 108 Waydroid 同血统、6 个必需 APEX 已解包、
SELinux 两边都是 Disabled。A 路线（真 init 当 PID1）的阻塞点只剩「PID1 + 属性区」两处。
你手上 minigbm/DRI 攻坚继续，不冲突；下面两件事是它的前置闸门，穿插做：

【E1｜属性区失败定因（半天，只读guest视角、不改镜像）】
  /system/bin/propinit（9,896B）已在镜像里，blobs/propfix/propinit.c:41-45 注释写着：
  guest 里 /dev/__properties__ 已存在，__system_property_area_init 对已存在区域返回 -1；
  但 B1 文档第 16 条记「先移除再建仍 -1」——归因未定。
  做法：guest 里跑一次 /system/bin/propinit 并抓它的 stderr（分叉都打出来了）。
  ⚠ 会 remove()+mkdir()，非只读——guest 重启即净，proppreload 不依赖该目录，回退=重启。
  判读（三条分支）：
    1) 「无法解析 libc 私有符号（area_init=0x0）」⇒ 符号解析问题，换 dlopen/dlsym 取法，成本最低；
    2) 「area_init=-1 且旧区已移除」⇒ 看 bionic 日志 errno：EPERM ⇒ SELinux 假设成立；
       EEXIST/EROFS ⇒ 挂载/权限问题，A 的属性区一步基本免费；
    3) 「area_init=0 但 add 失败」⇒ 卡在 per-context 文件，B 路线也变可行。
  结论写回 docs/research/framework/路线对比与推荐.md 的 E1 节。

【E2｜shadow PID1（请求 R1+R3，可回退）】
  做法：QEMU -append ... rdinit=/system/bin/init，现 /init 改名 /init.claw，
  用 init.claw.rc 把现有编排（挂载/adbd/harness/shim 注入）import 回去。
  ⚠ 必须一条命令能切回现路径（PID1 换错 guest 起不来）；建议做成 build_bootimg_inject.py 的开关。
  R3：让 propinit 把 errno/原因写到 /data/propinit.err（logd 不可用时 T4 只读探针可取）。
  成功判读：getprop | grep -c init.svc 从 0 变几十；失败判读：init panic 点 = A 的真实第一块石头。
  附带量一下 TCG 下 init 跑完 212 个 on 触发器的耗时（可能拖慢冷启动，A-1 阶段就要数）。

边界：只改 JavaBridge/qemu-src/** + JavaBridge/src/bridge/Server.java（你的领地）；
探针与文档归 docs/research/framework/** 可改；提交：中文 Conventional Commits，git commit -F。
```
