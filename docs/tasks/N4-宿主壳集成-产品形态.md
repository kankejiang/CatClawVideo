# N4｜宿主壳集成：把"只做显示"变成用户双击即用的产品

> 归属：**产品形态交付** —— 用户视角只有一件事：**打开 CatClawVideo，就看到 108 上那台真安卓的画面，
> 鼠标键盘直接在安卓里生效** ✗。
> 现状：**投屏链路已几乎可用** ✔ —— T3 服务端已验收通过 ✔（337 帧/22fps、输入注入生效 ✔）、
> T2 协议/渲染/输入已验证 ✔（29.8fps ✔），只差 T2 的 H.264 解码器（在写 ✗）。
> 本任务**不等** H.264 ✗：**先按 jpeg 兜底把产品壳做通** ✔，解码器落地后自动升级到 30fps ✔。

## 一、目标（一句话）

在 `CatClawVideo.Maui` 里做出：**连接页（地址/端口/编码 ✔）→ 一键连接 → 视频画面 + 键鼠注入 → 状态栏（fps/延迟/丢帧 ✔）→ 断线自动重连 → 退出** ✔。

## 二、任务

**【N4-1】把 T2 的客户端当**库**用（半天 ✗）**
- ⚠ **不要改 `tools/stream-probe/**`** ✗（T2 领地 ✗）。两种干净做法 ✔：
  1. 引用它的 **csproj** ✔（若它已把协议/解码拆成可复用类型 ✔ —— 先读一遍再决定 ✗）；
  2. 或**把协议客户端抽成新项目** ✗（如 `CatClawVideo.Stream/` ✗）⇒ **复制**协议实现而非改动原文件 ✔，
     并**通知 T2 窗口**你抽了哪些文件 ✗（避免两边各自演化 ✗）。
- 接口建议 ✔：`IStreamClient { Task ConnectAsync(host, port, codec); event FrameReady(byte[] data, codec); Task SendInputAsync(InputEvent e); Stats Stats { get; } }` ✔。

**【N4-2】宿主 UI（1 天 ✗）**
- `CatClawVideo.Maui` 加一个 **远程画面页** ✔：
  - 视频控件按**设备像素**等比缩放显示 ✔（握手行回传的 w/h ✗）；鼠标坐标 = **窗口坐标 ÷ 缩放比** ✔（HiDPI 必须处理 ✗）
  - 输入映射 ✔：左键点击/拖动 ⇒ 触摸 down/move/up ✔；滚轮 ⇒ 滚轮帧 ✔；键盘 ⇒ keycode ✔（含 HOME/BACK/ESC 映射 ✗）
  - 状态栏 ✔：实测 fps ✔、端到端延迟估算 ✔、码率 ✔、连接状态 ✔
  - 连接管理 ✔：地址/端口/编码可配 ✔ + **最近一次成功连接记忆** ✔ + 失败重试（指数退避 ✗）
  - 退出 ✔：`Esc` 或按钮 ⇒ 断开并复位 ✔
- 视觉要求 ✔：黑边不留白 ✗、缩放平滑 ✗、无撕裂（双缓冲 ✗）。

**【N4-3】一键启动与自检（半天 ✗）**
- 单文件启动 ✔（`CatClawVideo.Maui.exe` ✗）；启动时自检 ✗：
  - 108 可达性 ✔（TCP 探测 ✗）⇒ 不可达给**明确中文提示** ✔（"108 未启动服务端：请先执行 `bash serve.sh -d --port 27183`" ✗）
  - 可选 ✔：提供"帮我拉起服务端"按钮 ⇒ 后台 `ssh root@10.0.0.108 "cd /root/waydroid-stream && bash serve.sh -d --port 27183 --codec jpeg --fps 15"` ✔
- 判据 ✔：**在一台没装过环境的 Windows 上，按 README 三步内看到画面** ✔。

**【N4-4】回归（半天 ✗）**
- 连续 **30 分钟** ✔：内存不涨 ✗、fps 稳定 ✗、断线拔插 5 次能自动恢复 ✔；
- 记录表格入档 ✔：jpeg 兜底与 h264（若 T2 已交付 ✗）两条路线的 fps/延迟/带宽对比 ✔。
