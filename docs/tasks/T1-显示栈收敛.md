## 一、现状（全部有实测证据，勿从头再来）

guest 是"x86 mini ART"：QEMU `q35 + whpx` + Debian 内核 + 自建 initramfs，里面跑 Waydroid 的 Android 用户态组件。
**已经打通的部分**（见 `docs/B1-完成度与推进计划-20261001.md` 第 24~42 轮）：

| 环节 | 状态 | 关键做法/证据 |
|---|---|---|
| `/dev/dri` | ✅ | QEMU 加 `-device virtio-gpu-pci`；从 snapshot.debian.org 取**与内核精确匹配**的包（`linux-image-6.1.0-50-amd64` = `6.1.176-1`）抽 `drm*/virtio-gpu.ko`，init 里按依赖序 insmod |
| binder 三实例 | ✅ | guest 内核**无 binderfs**（`mount -t binder` 报 ENODEV）⇒ 用 classic 驱动 `devices=binder,hwbinder,vndbinder` 模块参数 |
| Android 服务栈 | ✅ | servicemanager / hwservicemanager / `allocator@4.0-service.minigbm_gbm_mesa`（=mapper@4.0）/ `composer@2.1-service` / `configstore@1.1-service` / `vendor.waydroid.task@1.0-service`（在**系统镜像**里）… 全部 `Registered …` |
| VINTF manifest | ✅ | 必须放 `/vendor/manifest.xml` 与 `/system/manifest.xml`（真机是 init 建软链）；vendor 侧**合并三份**（主清单 + gbm 的 allocator/mapper fragment）；**重复条目会让 libvintf 判非法 ⇒ 所有 HAL 查找失败**（踩过，打包器已加去重） |
| Wayland | ✅ | weston 14 以 **uid 1000** 运行、socket 在 `/run/user/1000`（Waydroid HWC 按 **uid 推算**该目录、忽略传入 env）；`busybox` **无 setuidgid** ⇒ 补 `/etc/passwd` 的 `system:x:1000` + `su system -c` |
| GL | ✅ | `ro.hardware.egl=angle` ⇒ loader 接受 ANGLE；ANGLE→Vulkan→**lavapipe**（需**真** `libLLVM22.so`，符号桩会毒死它 ✗）；`eglprobe` 实测拿到 **45 个 EGL 配置** |
| 诊断设施 | ✅ | `libpropfix.so`（属性 shim + dlopen/EGL 诊断 + 崩溃处理器）、`svccheck`、`eglprobe`、镜像自检 12 项 |

**当前唯一卡点**：SurfaceFlinger 启动后在 **HWC 回调**路径 abort ✗

```
SIGABRT  ←  liblog(__android_log_assert)
        ←  composer@2.1.so (BnHwComposerCallback::_hidl_onHotplug …)
        ←  composer@2.4.so (BnHwComposerCallback::onTransact …)
        ←  composer@2.1.so (BpHwComposerClient::_hidl_registerCallback …)
        ←  composer@2.1.so (BpHwComposerClient::registerCallback …)
        ←  surfaceflinger ×4        （SF 自身帧无法符号化：发布版 strip）
```
⇒ **Waydroid HWC 在 SF 注册回调时立刻回调 hotplug，SF 在回调处理中断言** ✗。
（另有一条更早出现过的 abort：`[alog:RenderEngine] output buffer not gpu writeable` ✗，可能同源或时序相关。）

## 二、目标与验收

**目标**：SurfaceFlinger **稳定常驻**（不 abort），并让 `adb exec-out screencap -p` **得到一张有效 PNG**。

**验收命令（必须贴原始输出）**
```powershell
# 1) 起应用（与测试分到不同命令，避免 kill job 连带杀掉 VM）
& 'CatClawVideo.Maui\bin\Debug\net11.0-windows10.0.26100.0\win-x64\CatClawVideo.Maui.exe'
# 2) 另一条命令里
$port = (Select-String "$env:APPDATA\CatClawVideo.debug\home-debug.log" 'adb 隧道已开：adb connect 127\.0\.0\.1:(\d+)' | Select-Object -Last 1)
adb connect 127.0.0.1:<port>
adb -s 127.0.0.1:<port> exec-out screencap -p > shot.png    # 期望：PNG（前 8 字节 89 50 4E 47）
adb -s 127.0.0.1:<port> shell ps -A                          # 期望：surfaceflinger 在
```
- ✅ 通过 = `shot.png` 是合法 PNG（`89 50 4E 47`）且 `surfaceflinger` 常驻
- ❌ 不通过 = `screencap` 阻塞/报 `Binder driver ... Permission denied`/SF 进程不在

## 五、已知坑（都踩过，别再踩）

1. **别把服务接进管道** ✗：`( svc | head -12 ) &` 会让服务在 head 退出后收 **SIGPIPE 而死** ✗（曾导致服务"注册后消失"、`screencap` 永久阻塞）。⇒ 重定向到 `/tmp/<svc>.log` ✔。
2. **VINTF 重复条目 = manifest 非法** ✗ ⇒ 所有 HAL 查找失败（症状伪装成"mapper 回归"✗）。
3. **图形服务的 `LD_LIBRARY_PATH` 必须含 `/system/lib64/egl`** ✗，否则 ANGLE 的 `libEGL_angle.so` 加载失败（报 `libGLESv2_angle.so not found` ✗）⇒ HWC 的 EGL 线程崩 ✗。
4. `eglChooseConfig` 遇到 `TRANSPARENT_TYPE` 会返回 0 个配置 ✗ ⇒ shim 已加"去掉该属性重试"✔（改动在此：`blobs/propfix/propfix.c`）。
5. `screencap` 在 adb shell(uid=shell) 下需要 `/dev/binder` 可读 ⇒ init 已 `chmod 666 /dev/binder /dev/hwbinder /dev/vndbinder` ✔。
6. **应用启动与 adb 测试分到不同命令** ✗（kill 掉后台 job 会把 VM 一起带走 ✗）。
7. `libpropfix.so` 的 `#if 0` 区块里**不能放类型定义/被引用的函数** ✗（曾导致 `egl_attr_name` 重定义/未定义 ✗）。
