# 调试报告：夸克网盘「保持登录状态」——2026-10-01 全天调查

> 目标：修好「夸克扫码后登录态不保持」（现象：扫码成功、toast 报会员，但状态永远未登录 / 卡在「加载中… 正在获取账号信息…」）。

---

## 一、结论摘要（TL;DR）

1. **今天修掉了 5 个真实缺陷**（都有提交号，见 §四），其中两个是硬阻塞：
   `Process.is64Bit()` 恒 false 导致加密层从未真正可用（失败 254 次）；
   `View.animate()` 返回 null 直接打死壳的初始化任务。
2. **新建了一个关键能力**：在 10.0.0.108 上跑起**真 Android 13（Waydroid + 我们自己的 ndk_translation）**，
   里面装着**用户手机上的同一个 TVBox APK + 同一份应用数据**，可 root adb 全面控制（§五）。
3. **夸克登录这个具体问题仍未解决**，但**四个假设被硬证据排除**（§三）：
   存储路径 ✗、WebView ✗、宿主端口探测 ✗、设备身份 ✗。
4. **今天最重要的发现**：在**真 Android**（真框架、真宿主 App、用户真实数据）里打开夸克网盘页，
   **同样是空白** ⇒ 那个「空白 / 加载中」**不是我们桩环境造成的**，问题在壳/宿主对这条页面的实现
   与其所需条件上（很可能与 WebView/Chromium 是否可用有关，见 §六）。

---

## 二、现象与关键观测

| 观测 | 数据 |
|---|---|
| 扫码后 toast | `夸克授权成功 [会员]`（说明扫码链路是通的） |
| 状态弹窗 | 永远 `夸克网盘 / 加载中... / 正在获取账号信息...`，从不出现用户名/SVIP/容量 |
| 壳自己的视图树 | 从未包含 `用户名/会员状态/存储容量/复制Cookie`（0 次）⇒ 是**它没拿到**，不是我们没画出来 |
| 壳的落盘 | prefs 只写 `app_cfg_v2`；`[sqlite]/[cookie]/[file]/[db]` 探针全 0；`/data/data`、`/data/user` 均不存在 |
| 网络 | pcap 双向配对：`uop.quark.cn` 1.7KB↑/19.0KB↓、`pan.quark.cn` 1.7/21.1、`drive.quark.cn` 1.3/16.7、`drive-pc.quark.cn` 4.5/69.6 ⇒ **与夸克通信正常** |
| 真机（手机）ground truth | 一次成功登录**只写 `spUtils.xml`**（明文 cookie，`quark_ck` 168 字符）；`files/quark_ut`(112B)、`quark_fid` 自 09-25 起未变 |

**推论**：cookie 只是钥匙；壳在「拿到钥匙之后」的那一步卡住，而且**它不是靠预存储的 cookie 决定状态的**
（我们把真机的 `spUtils.xml` 整份灌进 guest、壳也确实能用它播放，但状态依旧）。

## 三、已排除的假设（每条都有证据与方法）

| # | 假设 | 验证方法 | 结果 |
|---|---|---|---|
| 1 | 壳绕过我们的 Context 桩、用真框架写 `/data/user/0/<pkg>` | 桥启动即 dump `/data` 目录树（深度 2） | ✗ guest `/data` 下**只有** `catclaw/`（无 `/data/user`、无 `/data/data`） |
| 2 | 登录态存在我们没同步的文件里 | 手机端 5 分钟 md5/清单级监视（`spUtils.xml`/`quark_ut`/`quark_fid`/`databases`） | ✗ 成功登录只写 `spUtils.xml`，而它我们早已同步 |
| 3 | 壳用 WebView 取账号信息（真机登录那一分钟 `WebViewChromiumPrefs.xml` 被写） | 给 `WebView`/`WebSettings` 桩加全量留痕（URL/JS/注入接口/调用栈） | ✗ `[webview#`/`[websettings#` **计数 0** |
| 4 | `nc: can't connect to remote host (10.0.2.2)` 是壳在探测宿主端口 | 读 init 源码 + 统计 795 次 | ✗ 是**我们自己的调试后门**（while 每 2s 重试 18777，且绕过 `/bin/nc` 包装）—— 已改为 opt-in |
| 5 | 设备身份漂移（壳报给夸克的指纹不合法） | 手机 `getprop`/`settings` 取值 vs guest 桩；改齐后再扫 | ✗ 壳确实读了 4 次 `android_id` 并拿到真机同款值，**仍卡在加载中** |

> 说明：第 5 条虽被排除为**根因**，但修复本身保留（此前 `Settings.Secure.getString` 恒 null、
> `Build` 报 `CatClawVideo-Windows`，属真实隐患：其他站点会做指纹校验）。

## 五、新建能力：108 上的真 Android（B0）

**用途**：拿真框架做对照实验（我们今天用它证明了「真 Android 上网盘页也空白」）。

```bash
# 108 = Debian/Proxmox 主机，已装 Waydroid 1.6.2，binder 已加载，/dev/kvm 在
export XDG_RUNTIME_DIR=/run/user/0
# 1) 无头合成器（该机没有显示器，也不需要）
nohup weston --backend=headless --socket=wl-headless --width=1280 --height=720 &
export WAYLAND_DISPLAY=wl-headless
# 2) 容器配置要绑宿主 pulse socket，root 下没有 ⇒ 会 "Failed to setup mount entries"
mkdir -p /run/user/0/pulse && touch /run/user/0/pulse/native
# 3) 起会话（务必先 restart 容器服务，否则 waydroid0 网桥缺失、veth attach 失败）
systemctl restart waydroid-container
nohup waydroid session start &        # 等 Session: RUNNING
nohup waydroid show-full-ui &          # 保持窗口存活，否则 lxc-freeze 冻结容器
# 4) ARM 转译层（复用 QEMU guest 那套，见 /root/x86guest/mk_x86_initrd.sh）
NDK=/root/x86guest/vendor_google_proprietary_ndk_translation-prebuilt-11arm_13arm64/prebuilts
OV=/var/lib/waydroid/overlay/system; mkdir -p $OV
cp -a $NDK/lib64/. $OV/lib64/; cp -a $NDK/lib/. $OV/lib/; cp -a $NDK/bin/. $OV/bin/
#   + cpuinfo 覆盖 + ld.config.arm64.txt（同 mk_x86_initrd.sh 配方）
# 5) 属性（waydroid prop set 会 "Sending reply failed"，直接写文件可靠）
cat >> /var/lib/waydroid/waydroid_base.prop <<'P'
ro.dalvik.vm.native.bridge=libndk_translation.so
ro.enable.native.bridge.exec=1
ro.dalvik.vm.isa.arm64=x86_64
ro.dalvik.vm.isa.arm=x86
ro.product.cpu.abilist=x86_64,arm64-v8a,x86,armeabi-v7a,armeabi
ro.product.cpu.abilist64=x86_64,arm64-v8a
ro.product.cpu.abilist32=x86,armeabi-v7a,armeabi
P
# 6) 装 APK + 灌手机数据
adb connect 192.168.240.112:5555 && adb install -r -t /tmp/vbox-phone.apk
# 手机侧：adb exec-out run-as com.github.tvbox.osc.jun tar -cf - shared_prefs files databases > d.tar
cat d.tar | waydroid shell -- tar -xf - -C /data/data/com.github.tvbox.osc.jun
waydroid shell -- chown -R <uid>:<uid> /data/data/com.github.tvbox.osc.jun
# 7) 启动（launcher activity 是 com.github.tvbox.osc.ui.activity.HomeActivity）
adb shell monkey -p com.github.tvbox.osc.jun -c android.intent.category.LAUNCHER 1
```

**踩过的坑（都已解决）**
- 该机没有显示器 ⇒ 用 weston headless（不影响它的 KDE 桌面）。
- LXC 因缺 `/run/user/0/pulse/native` 直接 ABORT（日志只给 "container failed to start"，要 `lxc-start -l TRACE` 才看到根因）。
- `waydroid session stop` 会拆掉 `waydroid0` 网桥 ⇒ 重启会话前必须 `systemctl restart waydroid-container`。
- 容器没窗口时会被 `lxc-freeze` 冻结（画面停住、`adb` 命令全部无响应）⇒ 必须常驻 `show-full-ui`。
- arm64 APK 需要 native bridge 属性 + `abilist` 含 `arm64-v8a`，否则 `pm install` 直接失败。

## 六、未解之谜与下一步

**核心未解**：壳拿到夸克响应之后，为什么**既不落盘、也不产出账号信息**？
以及**真 Android 上网盘页也是空白**（说明这不是桩环境的锅）。

**候选路径（按投入排序）**

| 路径 | 做法 | 代价 | 能回答什么 |
|---|---|---|---|
| **B. 从手机同步 cookie** | 把「adb 到手机 → 读 `spUtils.xml` → 灌进 guest 持久化位」做成正式能力（现有 prefs 同步通道已具备） | 小 | 直接满足「登录能保持」的实际诉求（该 cookie 已证明在 guest 里播放正常、跨重启也在） |
| **C. 继续 B0** | 在真 Android 里查网盘页为何空白（Chromium/WebView 是否可用；对比手机环境） | 中 | 真框架下的正确行为，从而反推我们 guest 缺什么 |
| **A. MITM 看响应** | 让壳的 OkHttp 走我们的代理（系统代理 + 自签 CA 装进 guest 信任库），截获它对夸克的请求/响应 | 大 | 夸克到底回了什么；我们 guest 与真机的差异 |

**另外一条独立线索**：手机日志里壳在读 `/proc/net/tcp`
（`avc: denied { read } ... name="tcp"`）—— 它在检查本机 TCP 连接表，
这类「本地代理/端口探测」很可能是取账号信息的前置条件之一。
