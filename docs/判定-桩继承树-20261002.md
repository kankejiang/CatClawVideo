## 二、闸门的 4 类假阳性（每条都有具体样本，不是"大概"）

| # | bug | 样本（旧报数里的哪几条） | 修法 |
|---|---|---|---|
| ① | import 解析把**包名**当类全名：`import android.view.ViewGroup;` → 存成 `android.view` | LinearLayout/FrameLayout/ImageView/TextView/ProgressBar（桩父类=`android.view`）、Activity（`android.content`）、WebView（`android.widget`） | 全名 = 组1 + `"."` + 组2 |
| ② | javap 对**泛型类**输出 `class a.b.ArrayAdapter<T> extends a.b.BaseAdapter`，旧正则名字后直接要 `extends` | AdapterView、ArrayAdapter（都被判成 `java.lang.Object`） | 名字与 extends 之间允许 `<...>`，父类也剥掉 `<...>` |
| ③ | **java.lang 隐式导入**没解析成全名就比对 | ActivityNotFoundException（`RuntimeException` vs `java.lang.RuntimeException`） | `resolve()` 返回**候选集**（本包/import/java.lang/原样），真机父类落在集合里即一致 |
| ④ | 取的是"文件里**第一个** extends"，不是本文件那个类的 | PackageManager（其实是嵌套的 `NameNotFoundException extends Exception`）、Resources（同形） | 正则锚定类名 = 文件名的那个声明 |

自检里补了 ①②③ 三类作为"必须不再误报"的用例（④ 的回归证据是这两条从输出里消失）。

## 三、11 处真错：全是"桩少写一层中间父类"

真机链一律以 `android.jar(API 33)` 的 javap 输出为准：

| 桩类 | 桩原来 | 真机 | 本次动作 |
|---|---|---|---|
| `android.app.Activity` | `extends android.content.ContextThemeWrapper`（**包放错**） | `android.view.ContextThemeWrapper` | 文件移到 `android/view/`，`extends android.content.ContextWrapper`，Activity 的 import 跟着改 |
| `android.content.ClipboardManager` | Object | `android.text.ClipboardManager` | 新建 `android/text/ClipboardManager`（abstract 标记父类） |
| `android.content.pm.ApplicationInfo` | Object | `android.content.pm.PackageItemInfo` | 挂到已有的 `PackageItemInfo` |
| `android.content.pm.ProviderInfo` | `PackageItemInfo` | `ComponentInfo` | 新建 `ComponentInfo extends PackageItemInfo`，ProviderInfo 挂它 |
| `android.graphics.drawable.StateListDrawable` | `Drawable` | `DrawableContainer` | 新建 `DrawableContainer extends Drawable` |
| `android.os.Bundle` | Object | `BaseBundle` | 新建 `BaseBundle`（纯标记） |
| `android.view.KeyEvent` / `MotionEvent` | Object | `InputEvent` | 新建 `abstract InputEvent`，两个事件类挂它 |
| `android.webkit.WebView` | `FrameLayout`（分支也不对） | `AbsoluteLayout` | 新建 `AbsoluteLayout extends ViewGroup`（带 `()`/`(Context)`/`(Context,AttributeSet)` 构造器），WebView 改挂它 |
| `android.widget.ListView` | `AdapterView<ListAdapter>` | `AbsListView` | 新建 `abstract AbsListView extends AdapterView<ListAdapter>`（构造器同上） |
| `android.widget.SeekBar` | `ProgressBar` | `AbsSeekBar` | 新建 `abstract AbsSeekBar extends ProgressBar`（含 3 参构造器 —— `SeekBar` 会 `super(c,attrs,defStyle)`） |

### 为什么中间类做成"纯标记父类"（不写成员）

1. **不造静默丢数据**：给 `BaseBundle`/`InputEvent` 写 `size()→0`、`getSource()→0` 这类返回常量，
   就是 `check_stubs.py` 一直在拦的"恒 null/恒 0 getter"型坑（历史上静默丢过数据）。
2. **只赚不亏**：补这一层之前，桩命名空间里**根本没有** `AbsListView`/`InputEvent` 这些类，
   引用它们的字节码本来就跑不通（`NoClassDefFoundError`）；加一个空父类把继承链接上，
   唯一变化是"当父类型用"这条校验能过了，不会改坏任何现在能跑的路径。
   成员等出现真实调用点、能给出返回值语义时再按调用点补。
3. 子类需要的成员仍从原父类链继承（`AbsListView → AdapterView`、`AbsSeekBar → ProgressBar`），
   所以 `ListView.getAdapter()`、`SeekBar.setProgress()` 这些照旧可达。

### 编译期真的抓到过两件事（不是"看起来对"）

- `AbsoluteLayout` 忘了 `import android.view.ViewGroup` ⇒ 找不到符号；
- 中间类只给无参构造器 ⇒ 子类的 `super(c)` / `super(c, attrs, defStyle)` 全部编不过
  （ListView/WebView/SeekBar 三处）。**这就是"改完必须编译"的理由**：静态判据看继承树是绿的，
  Java 层面其实已经断了。

## 四、判读规则（下次闸门再报错时按这个走）

1. 闸门报错 ≠ 桩真错：先排 ①②④ 四类假阳性（`--explain` 会把候选全名集打出来，一眼能看是不是解析问题）。
2. 真错的定义：**能指出谁会把该对象按父类型使用**（壳的字节码形参/接收者/checkcast），
   或 ART 已经报过 `VerifyError`。说不出来的记为"待判"，不要顺手改桩。
3. 补中间类时：链接对 + 构造器齐（子类的 `super(...)` 形状要逐个看），成员一律先不造。
4. 改完必须：`javac` 全树编译过 + `check_stubs.py` + `check_stub_parents.py` + `--selftest` 四连绿；
   运行期确认要等镜像重建窗口（产物是别的会话在飞文件时不要抢）。
